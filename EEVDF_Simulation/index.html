How EEVDF works

What is EEVDF?

A proportional-share scheduler. Each task gets CPU time in proportion to its weight, and latency is controlled by choosing the task whose virtual deadline is earliest among those that are owed CPU time.

Virtual runtime

v += 1 / weight for every tick executed. Heavy tasks age slowly, so they run more often.

Virtual time and lag; eligibility

V = Σ(w·v) / Σw over runnable tasks. lag = w·(V − v). A task is eligible when lag ≥ 0, meaning it has not received more than its fair share. New tasks join with v = V (lag 0).

Virtual deadline

When a task requests a slice of q ticks: d = v + q / w. After finishing a slice it requests a new one and d is recomputed.

Selecting the next task

At each slice boundary: 1) compute V, 2) discard tasks with lag < 0, 3) pick the smallest d among the rest (ties: lower task number). An ineligible task is skipped even if its deadline is earlier. That is what separates EEVDF from plain EDF.

Difference from CFS

CFS always runs the task with the smallest vruntime and uses sleeper heuristics for latency. EEVDF uses lag for fairness and the deadline, derived from the requested slice, for latency.

This model vs. Linux

Simplified: one CPU, integer ticks, fixed slice for all tasks, no wakeup preemption, no nice-to-weight table, no lag clamping or placement of sleeping tasks, no cgroups, no load balancing, no fixed-point arithmetic.
